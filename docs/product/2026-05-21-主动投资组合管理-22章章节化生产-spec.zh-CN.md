# 《主动投资组合管理》22 章章节化 Web Deck 生产 Spec

状态：拟执行

适用运行形态：Codex 自然语言入口 -> `chapter_guided` 规划 -> Codex authored bundle -> imagegen 图片资产 -> preview 发布

## 1. 目标

把《主动投资组合管理》做成一套面向学生自学的中文学术 Web Deck。

目标产物不是教师课件，也不是章节摘要页面，而是：

```text
按章节拆分的学生自学型学术 Web Deck
```

最终目标规模：

- 1 个全书总览单元
- 22 个章节单元
- 每章默认 12 页
- 章节之间保持章节映射，但内容表达服务于自学，不服务于授课提示

## 2. 为什么不能直接一次性铺开 22 章

这本书按 `22 章 x 12 页` 计算，单章节内容页就有：

```text
264 页
```

再加总览单元，已经属于完整教材级 Web Deck，而不是小课程包。

当前已经验证通过的只有两件事：

1. `chapter_guided` 在真实书籍资料上能稳定规划章节单元。
2. `overview` 单元的真实 imagegen 图片链路已经跑通。

还没有验证通过的是：

1. 单章 12 页是否会开始水化、模板化。
2. 大批量 imagegen 是否会重新退化成同构图换颜色。
3. 长书场景下章节之间是否会出现高重复表达。
4. `authoring -> imagegen -> layout -> publish` 是否能在章级批量上稳定闭环。

所以必须先做章节试点，再批量铺开。

## 3. 本轮范围

### 3.1 本轮必须完成

1. 写清全书章节化生产路线。
2. 先试点 `chapter-01` 和 `chapter-02`。
3. 每章目标 12 页。
4. 每页必须进入真实 `imagegen` 图片流程。
5. 试点通过后，再按批次扩到全书 22 章。

### 3.2 本轮不做

1. 不做 teacher mode。
2. 不做 quiz-first 互动课。
3. 不做额外 playground。
4. 不为了“形式完整”提前写满全部 22 章。
5. 不允许用 placeholder 图片充当正式 learner preview 资产。

## 4. 目标用户与内容定位

目标用户：

- 有一定金融、投资、量化基础，但没有系统建立主动组合管理心智模型的中文学习者
- 大学高年级、研究生、行业研究者或希望快速建立框架的从业者

内容定位：

- 不是“如何炒股”的通俗内容
- 不是给老师的讲课脚本
- 是围绕主动收益、风险分解、预期收益、一致性、组合构建、业绩归因等核心问题展开的紧凑教材型页面

页面要让学习者读完后获得：

1. 这章到底解决什么问题
2. 作者提出了什么判断框架
3. 关键公式、机制、变量、假设如何互相连接
4. 这个判断在什么条件下成立、在什么条件下会失效

## 5. 课程组织形态

### 5.1 整体形态

默认组织：

1. 全书总览单元
2. 第 1 章到第 22 章的章节单元

总览单元负责：

- 建立全书问题域
- 说明主动管理不是经验集合，而是判断系统
- 给出后续章节的认知地图

章节单元负责：

- 对应书中原章节
- 在保留章节映射的前提下，重写为自学型教材页
- 不机械照搬目录小标题

### 5.2 每章 12 页的默认预算

每章默认 12 页，但这 12 页不是固定模板，只是页数预算。

推荐分布：

1. 章节问题与位置
2. 章节核心命题
3. 概念或变量拆解
4. 机制链路 1
5. 机制链路 2
6. 公式/框架解释
7. 例子或情境
8. 判断边界或失败条件
9. 与上一章/下一章的连接
10. 经典误读修正
11. 章节压缩判断
12. 章节收束与迁移

注意：

- 这不是 learner-facing 固定栏目。
- Codex 必须根据章节内容自主决定每页知识结构。
- 如果某章更适合“公式解释 + 例子 + 边界”，就不要硬凑“误读修正页”。

## 6. 单页生产合同

每页必须遵守当前权威产品规范：

1. 标题：一个具体命题、判断或真实问题。
2. 中间区域：真实图片 + 正文讲解。
3. 底部一句话：可复习的压缩判断。

页面禁止出现：

- 教学目标、课堂提示、教师话术
- “判断入口 / 推理链路 / 证据边界 / 自检问题”这类固定栏目名
- rubric 语言、reviewer 语言、流程语言
- 标题、图片、正文、底部总结互相复读

每页至少要交付一个学术判断，且尽量同时满足：

- 明确命题
- 机制解释
- 来源依据
- 适用边界
- 必要术语精度

## 7. 图片生产合同

本项目这本书的章节化生产，图片规则必须更严格：

1. 每页中间区域默认只消费真实图片资产。
2. 图片必须由 Codex 先做内容设计，再交给 `imagegen` 生成。
3. 图片资产必须记录 provenance，且 `generator=imagegen`。
4. placeholder、SVG、程序化伪图示、表格、UI 面板图都不能作为默认 learner 预览图。
5. Codex 直接调用内置 `imagegen` 工具生成图片；生成文件默认落在 `$CODEX_HOME/generated_images/<session-id>/`，必须再通过 `learning_agent.record_imagegen_batch_item` 或 `learning_agent.record_imagegen_asset` 写入 `runs/<runId>/preview/images/...`。

图片内容要求：

- 突出知识关系、变量结构、判断方向、因果或权衡
- 可以有短标签
- 不允许大段文字
- 不允许把页面标题或底部一句话重复写进图片
- 不允许同构图只换颜色

章节批量生产时，要重点防两类退化：

1. 同一章 12 页图片构图越来越像
2. 不同章节复用同一图骨架，只改术语

本书试点确认的图片验收信号：

- `visualSpec.imageUrl` 只是目标路径，不代表图片已经存在。
- 浏览器能渲染的前提是 preview 图片 URL 返回 200。
- `validate_imagegen_assets.status` 必须为 `passed`。
- provenance 必须显示 `generator=imagegen`，不能是 `placeholder` 或 `unknown`。
- layout smoke 中每页都应有 `imageCount=1` 和 `loadedImageCount=1`。

## 9. 内容质量门禁

### 9.1 必须拦截的失败模式

以下任一出现，都不应发布为 learner-facing 正式预览：

1. 教师课件味重
2. 学术密度不足
3. 页面只在讲学习方法，不在讲知识
4. 固定栏目模板味明显
5. 标题、图片、正文、总结互相复读
6. 图片只是换颜色的重复骨架
7. 章节页大量重复相同判断句
8. 关键公式或变量关系被压扁成泛泛概念

### 9.2 章节级合格标准

单章 12 页要达到：

- 每页至少 1 个明确知识动作
- 至少 4 页带有较强机制解释
- 至少 2 页带有例子/情境/案例分析
- 至少 2 页明确讲边界、假设或失败条件
- 章节结尾能压缩成一条可复习判断

### 9.3 全书级合格标准

全书铺开后要达到：

- 章与章之间有明显层次推进
- 不同章节不是只换术语复用同一写法
- 总览与章节单元之间职责清楚
- 重要章节的知识密度明显高于总览页

## 10. 运行时与发布要求

每章生产要沿当前默认工作流：

1. `learning_agent.prepare_learning_course`
2. Codex authored `coursePack + lessons`
3. `learning_agent.publish_learning_course`
4. `learning_agent.create_imagegen_manifest`
5. `learning_agent.record_imagegen_asset` 或 batch 工具
6. `learning_agent.validate_imagegen_assets`

- 不让学习者审批 authoring / imagegen 细节
- 只在最终阶段给出 preview URL、课程结构、质量摘要

## 12. 风险与回退策略

### 风险 1：单章 12 页开始水化

处理：

- 允许某章先做成 10 页试运行，再补足到 12 页
- 补页必须增加知识价值，不能只补总结和复述

### 风险 2：图片批量退化成同构图

处理：

- 每批次先抽样看 2 章
- 不合格时先修图片 prompt 规则，再继续批量

### 风险 3：章节间表达重复

处理：

- 强化章节角色区分
- 每章先写“本章独有判断”
- 如果写不出本章独有判断，说明这一章的生产策略有问题，不能直接扩页

### 风险 4：布局被 12 页密度压坏

处理：

- 单章发布前跑 layout smoke
- 必要时针对章节页面收紧图片比例和文字区布局
