# Milestone C Codex Authoring Quality Kernel Spec

Date: 2026-05-07

## Final Goal

Make Codex, Claude, or a similar agentic coding environment the primary authoring entry, while the learning-agent MCP and skills act as a course-quality operating system.

Milestone C is complete when a source-backed Chinese course generated through Codex-authored flow can be checked against a stricter quality contract that detects shallow summaries, generic pages, weak source synthesis, decorative interactions, missing feedback mechanisms, and difficulty mismatch before learners see the course.

## Product Position

The entry is not a standalone app. The intended product surface is:

1. Learner talks to Codex, Claude, or a similar agent.
2. Agent calls `learning_agent.prepare_learning_course`.
3. MCP returns source semantics, recommended units, content blueprint, and authoring constraints.
4. Codex authors the actual course pack, lessons, visual design, interactions, and feedback.
5. MCP validates, publishes, compares, revises, previews, and exports.

The product advantage is not replacing the large model. It is using the large model under a strict learning-design protocol.

## P0: Codex Authoring Protocol V2

Goal: Codex must have a clear, reusable contract for writing courses.

Required behavior:

- Document the authoring sequence from source semantics to lesson pages.
- Require each page to state a mental-model move, source usage, learner action or check, and feedback mechanism.
- Require difficulty-specific expectations for:
  - undergraduate core
  - upper-undergraduate / graduate
  - research reading
  - practical engineering
- Require source-backed courses to transform source material into a learning structure, not merely summarize anchors.
- Require visual and interaction design to be generated by Codex when topic-specific pedagogy needs it.

Acceptance:

- A protocol doc exists under `docs/runtime/`.
- The operator and source-to-course skills reference the protocol.
- Bundle checks ensure the protocol is shipped to seed users.

## P1: Critical Quality Checks

Goal: Quality checks should identify common failures in Codex-authored courses.

Required behavior:

- Detect generic overview pages that contain boilerplate learning language but no source-specific terms or mechanism.
- Detect weak source synthesis when source anchors exist but the page text does not use source-specific concepts or evidence language.
- Detect shallow academic depth for graduate/research courses.
- Detect decorative or vague interactions whose `cognitivePurpose` does not teach cause, structure, prediction, misconception, decision, comparison, or transfer.
- Expose these issues through `CourseQualityReport` categories and authored-vs-draft comparison metrics.

Acceptance:

- Tests fail on generic, source-anchored-but-unspecific pages.
- Tests fail on vague interactions.
- Tests pass on source-specific pages that include mechanism, evidence, limitation, learner action, feedback, and transfer.
- Authored-vs-draft comparison reports generic and weak-synthesis gaps when authored content regresses.

## P2: Real Source Quality Benchmark

Goal: Keep course quality improvements tied to varied source types.

Required behavior:

- Maintain a benchmark spec covering book, paper, patent, blog, documentation, notes, and topic-only requests.
- For each source type, record the quality dimensions that should be checked.
- Ensure the regression suite exposes semantic, grounding, interaction, and depth expectations.
- Avoid committing private or copyrighted generated course content.

Acceptance:

- A benchmark doc exists and is referenced by runtime docs or skills.
- Existing real-source regression samples are extended with quality focus expectations.
- Automated tests verify the benchmark includes all target source kinds and the key quality dimensions.

## Non-Goals

- Do not build a standalone user-facing app in this milestone.
- Do not make deterministic generation the default high-quality path.
- Do not hard-code a domain-specific lesson generator for one topic.
- Do not require learners to approve internal artifacts.

## Final Acceptance

Milestone C is complete when:

- `docs/runtime/codex-authoring-protocol-v2.md` exists and is included in bundle checks.
- `CourseQualityReport` can flag generic pages, weak source synthesis, weak academic depth, and decorative interaction.
- `AuthoringQualityComparisonService` exposes the same risks as authored-vs-draft metrics/gaps.
- The real-source benchmark records quality expectations for book, paper, patent, blog, documentation, notes, and topic-only inputs.
- Targeted tests and `npm run release:check` pass.
