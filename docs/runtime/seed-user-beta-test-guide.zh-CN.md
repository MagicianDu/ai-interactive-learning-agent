# 种子用户 Beta 测试说明

适用版本：`beta/2026-06-02-seed`

适用对象：愿意在本地使用 Codex 或兼容 MCP 客户端试用“资料 -> 中文自学 Web Deck”流程的技术型种子用户。

## 测试目标

请验证 AI Interactive Learning Agent 是否能把一本书、一篇论文、一个专利页面或一篇技术博客，转成面向学生自学的中文 Web Deck 预览。重点看：

- 课程是否按你的资料、受众、教学难度和组织方式生成。
- 页面是否有明确学术判断、机制解释、证据依据和适用边界。
- 互动、测验、反馈和迁移任务是否真正帮助理解，而不是装饰。
- 来源依据是否能支撑页面内容；不能支撑的背景是否被标成推断或类比。
- 反馈修订后，预览是否能更新到更符合你要求的版本。

## 当前稳定测试范围

优先测试这些来源类型：

- `book`：可抽取文本的书籍 PDF、Markdown 或文本文件。
- `paper`：论文 PDF、Markdown 或文本文件。
- `patent`：公开专利 URL。
- `blog`：公开技术博客 URL。

可以探索但暂不作为稳定承诺的来源类型：

- `documentation`
- `notes`
- `topic-only`

## 本地安装和启动

在项目目录运行：

```bash
npm install
npm run codex:bundle:install
npm run codex:mcp:check
npm run dev
```

浏览器打开：

```text
http://127.0.0.1:5173/
```

Codex 或 MCP 客户端重启后，应能看到 `learningAgent` MCP 服务。

## 推荐测试请求

把下面模板贴给 Codex，并替换资料路径或 URL：

```text
请使用 learningAgent，把 <资料路径或 URL> 生成中文自学型 Web Deck。
sourceKind=<book|paper|patent|blog>。
面向有相关基础但需要建立系统心智模型的中文学习者。
教学难度=大学高年级/研究生课程。
课程组织方式=先总览，再按核心 topic 拆成多个单元。
每个单元 8 页。
不要让我审批内部 artifacts；请生成可预览课程，并给我 preview URL。
```

如果 Codex 追问资料范围、教学难度、页数或组织方式，只回答这些用户可理解的问题。不要进入 source map、concept map、critic report 等内部审批流程。

## 预期交付

一次成功测试至少应得到：

- 一个 preview URL，通常形如 `http://127.0.0.1:5173/#/preview/<run-id>`。
- 一个课程总览和多个单元。
- 每个单元有页面导航、来源依据、互动或检查、总结和迁移任务。
- `qualityReport.status=passed`。
- 用户反馈后，可以得到修订后的预览。

## PDF 和来源限制

可抽取文本的 PDF 才适合作为 `book` 或 `paper` 测试资料。扫描版、图片型 PDF、加密 PDF、抽取不到文字的 PDF 会被系统阻断；这不是崩溃，而是为了避免生成没有来源支撑的内容。

遇到这种情况，请改用：

- 已 OCR 的 PDF。
- Markdown、TXT、HTML 等可读文本。
- 公开 URL。
- 你手动摘出的章节文本。

不要把不可抽取 PDF 的阻断当作课程质量问题；请在反馈里标成“来源抽取问题”。

## 反馈模板

请按下面格式反馈：

```text
runId:
sourceKind:
资料类型和路径/URL:
我的原始请求:
预览 URL:
是否能打开页面:

具体页面或单元:
期望改成什么:

```

## 不要测试的内容

这次 beta 不验证：

- 多用户账号、云端存储或权限控制。
- 面向课堂授课的教师模式。
- 完全自动的云端 SaaS 流程。
- 对所有 PDF 格式的无条件支持。
- 版权受限资料的公开分享。

## 隐私和版权边界

默认流程在本地运行。请确认你有权使用输入资料，并避免把受版权限制或含敏感信息的生成预览公开分发。导出课程前，先检查页面中是否包含不应外传的原文片段、个人信息或内部资料。

## 测试完成标准

一位种子用户完成一次有效测试，至少需要：

1. 按说明启动项目和 MCP。
2. 用一个稳定范围内的来源生成课程。
3. 打开 preview URL 并浏览至少一个完整单元。
4. 提交一次具体反馈。
5. 查看修订后的预览或记录修订失败原因。
6. 按反馈模板提交结果。
